# 商用验收条（AI 每次相关改动对照）

本项目按**可商用**标准开发。下面不是「有空再做」，而是 **默认门槛**：相关改动触及某条时，必须满足或明确记录缺口与风险（并尽量当场补齐）。

## 1. 安全验收

| ID | 条项 | 验收方式 |
|----|------|----------|
| S1 | 未登录不能改玩家资产/敏感状态 | 调 API 无 token → 401 |
| S2 | 不能仅靠 body 里的 account 冒充他人 | 改 account 字段应失败并宜记 anomaly |
| S3 | 管理接口匿名不可用 | 无管理凭证 → 401/403 |
| S4 | SQL 无拼接注入点 | 代码审查：用户输入只走占位符 |
| S5 | 静态不可下载 DB/源码/git/env | `/players.sqlite`、`/server.js`、`/.env` → 404 |
| S6 | 生产弱口令不可用 | `NODE_ENV=production` 缺强密钥应拒绝启动或等价保护 |
| S7 | 密码与 token 不进日志/仓库/前端本地明文 | 搜 diff：无 password 明文写盘 |
| S8 | XSS 不因新面板扩大 | 动态 HTML 转义或 DOM API |

## 2. 经济与公平性验收

| ID | 条项 | 验收方式 |
|----|------|----------|
| E1 | 奖励服务端计算 | 客户端改奖励 payload 无效 |
| E2 | 重复请求不双发（幂等/冷却/次数） | 连点两次领奖，资产只加一次或第二次明确拒绝 |
| E3 | 交易/转移原子性 | 中断或并发下不复制物品 |
| E4 | 兑换码有限次/时效/每号限制（若适用） | 库配置或等价服务端规则 |
| E5 | 异常数值可观测 | 作弊尝试有 anomaly 或拒绝原因 |

## 3. 可维护性验收

| ID | 条项 | 验收方式 |
|----|------|----------|
| M1 | 新业务不在 app.js/server.js 膨胀 | diff 入口仅接线 |
| M2 | 领域目录 + 导出清晰 | 有 README 或文件头说明 |
| M3 | 无双份逻辑源 | 全局搜索无复制粘贴分叉 |
| M4 | 协议/落点文档同步 | API 或 AGENTS §3 已更新 |
| M5 | Git 历史可回滚 | 小步、message 清晰、无密钥文件 |

## 4. 稳定性验收（最低）

| ID | 条项 |
|----|------|
| R1 | 服务器可启动 |
| R2 | 主路径不因新功能空引用导致白屏/进程崩溃 |
| R3 | WS 断开不泄漏房间引用（若改了 WS） |

## 5. AI 输出要求

完成任务时，在总结中用简短列表标明：

- 落点目录  
- 入口是否仅接线  
- 触及的安全/经济条（S*/E*）如何满足  
- Git：分支、commit hash/message（若已提交）  
- 已知残余风险（若有）
