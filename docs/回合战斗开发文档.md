# 回合制战斗系统复刻开发文档

本文档是一份纯文字规格说明，用于在任意编程语言、任意客户端或服务端框架中复刻同类回合制战斗系统。内容覆盖 PVE、PVP、组队 PVP、控制逻辑、自动战斗、战斗动画、战斗站位、事件播放与网络同步。

本文档不要求开发者使用特定语言。只要实现相同的数据模型、回合规则、表现事件和同步流程，就可以在网页、Unity、Godot、Cocos、原生 App、服务端脚本或其他系统中复刻。

## 1. 系统目标

该战斗系统是多人在线 RPG 的回合制战斗。

核心目标：

- 支持玩家对怪物的 PVE 战斗。
- 支持玩家对玩家的单人 PVP。
- 支持队伍对队伍的组队 PVP。
- 支持人物、宠物、佣兵共同参战。
- 支持手动下达指令和自动战斗。
- 支持速度决定行动顺序。
- 支持技能、状态、被动、治疗、复活、吸血、连击、反击等机制。
- 支持战斗动画、伤害数字、状态图标、技能名、战斗日志。
- PVP 战斗结果必须由服务端权威计算，客户端只播放结果。

## 2. 战斗基本概念

### 2.1 战斗参与者

战斗参与者分为两层概念。

第一层是场景角色，也就是进入战斗前在地图或系统中存在的对象。它可以是玩家、宠物、佣兵、怪物、Boss 或竞技场镜像。

第二层是战斗单位，也就是进入战斗后由战斗引擎使用的对象。战斗单位保存当前生命、最大生命、状态、增益、是否阵亡、战斗站位和行动信息。

复刻时建议保持这两层分离。场景角色负责地图表现，战斗单位负责规则计算。

### 2.2 阵营

一场战斗固定分为两边：

- 我方阵营
- 敌方阵营

在 PVE 中，我方通常是玩家队伍，敌方是怪物队伍。

在单人 PVP 中，服务端可以约定攻击方是我方阵营，防守方是敌方阵营。防守方客户端即使看见自己在画面左侧或右侧，也不影响服务端内部阵营定义。

在组队 PVP 中，攻击队伍为一方，防守队伍为另一方。

### 2.3 参战单位类型

每个玩家最多可以带三类单位进入战斗：

- 人物：玩家本体，主要受玩家手动控制。
- 宠物：玩家携带的宠物，可以手动或自动控制。
- 佣兵：玩家携带的佣兵，可以手动或自动控制。

怪物和 Boss 也可以被当作人物类单位处理，只是它们由自动逻辑控制。

## 3. 战斗属性

每个战斗单位至少需要以下属性：

| 属性 | 含义 |
| --- | --- |
| 生命 | 当前生命和最大生命 |
| 攻击 | 物理伤害来源 |
| 防御 | 降低受到的普通伤害 |
| 速度 | 决定回合内行动顺序，也可参与部分技能伤害 |
| 法力 | 魔法技能伤害来源 |
| 暴击率 | 触发暴击的概率 |
| 暴击伤害 | 暴击时的伤害倍率 |
| 技能列表 | 当前单位可用的主动和被动技能 |

可选属性：

| 属性 | 含义 |
| --- | --- |
| 穿甲 | 无视目标部分防御 |
| 伤害减免下降 | 降低目标防御带来的减伤效果 |
| 属性倍率 | 对全属性或单项属性做倍率修正 |
| 格挡减伤 | 按攻击者类型降低受到的伤害 |
| 复活概率 | 死亡时概率复活 |
| 吸血比例 | 造成伤害后按比例恢复自己 |
| 控制免疫 | 免疫控制状态 |

## 4. 技能系统

### 4.1 技能类型

技能分为以下类型：

| 类型 | 说明 |
| --- | --- |
| 物理技能 | 主要根据攻击、速度等属性造成伤害 |
| 魔法技能 | 主要根据法力造成伤害 |
| 特殊技能 | 通常用于施加控制或异常状态，可不造成伤害 |
| 治疗技能 | 恢复己方生命，可附带复活或净化 |
| 自身增益 | 强化施法者自身，例如加生命、免控、吸血、复活 |
| 团队增益 | 强化己方多个单位 |
| 被动技能 | 不需要主动释放，战斗开始或行动过程中自动生效 |

### 4.2 技能常见参数

一个技能可以包含以下参数：

| 参数 | 说明 |
| --- | --- |
| 技能名称 | 播放技能名和日志使用 |
| 技能类型 | 物理、魔法、特殊、治疗、增益、被动 |
| 攻击系数 | 用攻击属性计算伤害 |
| 法力系数 | 用法力属性计算伤害 |
| 防御系数 | 用自身防御属性计算伤害 |
| 速度系数 | 用速度属性计算伤害 |
| 当前生命比例伤害 | 按目标当前生命计算额外伤害 |
| 固定伤害 | 无视普通伤害公式，直接造成固定数值 |
| 是否无视防御 | 防御减伤是否失效 |
| 是否允许暴击 | 部分技能不能暴击 |
| 目标规则 | 单体、全体、多个目标 |
| 控制概率 | 混乱、封印、眩晕、沉睡、束缚、麻痹等概率 |
| 状态持续回合 | 控制或异常状态持续多久 |
| 流血或诅咒数值 | 回合末扣血 |
| 治疗比例 | 按最大生命恢复 |
| 是否复活 | 治疗是否能救起阵亡单位 |
| 是否净化 | 是否移除控制和异常状态 |
| 增益回合 | 增益持续多久 |
| 施放前置 | 职业、武器、特殊装备、献祭队友等条件 |

### 4.3 技能可用性

判断一个单位能否使用某技能时，按以下顺序检查：

1. 技能是否存在。
2. 技能是否为主动技能；被动技能不能主动释放。
3. 单位是否被封印；被封印时不能使用技能。
4. 技能是否要求特定职业。
5. 技能是否要求特定武器或特殊装备。
6. 技能是否要求献祭宠物、佣兵或其他单位。
7. 献祭目标是否仍然存活。

如果技能不可用，推荐降级为普通攻击，而不是中断整个回合。

## 5. 伤害公式

### 5.1 有效属性

计算战斗时不要直接使用基础属性，应先计算有效属性。

有效属性等于基础属性加上增益值，然后乘以属性倍率。

如果某个单位有全属性倍率，则所有属性都受影响。如果某个单位有单项属性倍率，则该属性优先使用单项倍率。

### 5.2 基础伤害

技能基础伤害由多个属性按系数相加：

- 攻击乘以攻击系数
- 法力乘以法力系数
- 防御乘以防御系数
- 速度乘以速度系数
- 目标当前生命乘以生命比例系数

普通攻击可以视作一个默认技能：攻击系数为 1，法力系数为 0.35，其他系数为 0。

### 5.3 防御减伤

目标防御会降低受到的伤害。推荐公式：

防御减伤等于有效防御除以有效防御加 100000。

防御减伤最高不超过 90%。

如果攻击技能带穿甲，则有效防御先乘以一减穿甲比例。

如果目标处于破甲状态，则有效防御视为 0。

如果目标处于易伤状态，则从防御减伤中扣除易伤值，但最终减伤不能低于 0。

### 5.4 格挡减伤

目标可以根据攻击者类型拥有不同格挡减伤：

- 减少来自人物的伤害
- 减少来自宠物的伤害
- 减少来自佣兵的伤害
- 自身增益提供的通用格挡减伤

如果多个格挡来源同时存在，取最高值。

### 5.5 暴击

如果技能允许暴击，则按攻击者暴击率判定。

暴击率上限建议为 100%。

暴击伤害上限建议为 2000%。

暴击后最终伤害乘以暴击伤害倍率。

固定伤害默认不暴击。

## 6. 状态系统

### 6.1 控制状态

| 状态 | 效果 |
| --- | --- |
| 束缚 | 无法行动 |
| 沉睡 | 无法行动 |
| 眩晕 | 无法行动 |
| 麻痹 | 无法行动 |
| 混乱 | 随机攻击任意其他存活单位，包括队友 |
| 封印 | 不能使用技能，只能普通攻击 |

单位拥有控制免疫时，不应被新控制状态影响。

### 6.2 持续伤害

持续伤害在回合末结算。

流血：每回合末扣固定伤害或由技能属性计算出的伤害。

诅咒：每回合末扣固定伤害或根据施法者法力计算出的伤害。

持续伤害可以导致单位阵亡，也可以触发复活。

### 6.3 增益和减益

| 状态 | 效果 |
| --- | --- |
| 易伤 | 降低防御减伤 |
| 破甲 | 防御视为 0 |
| 减速 | 降低速度倍率 |
| 速度提升 | 增加速度 |
| 暴击提升 | 增加暴击率 |
| 绝世增益 | 可包含免控、全属性倍率、复活概率提升等 |

状态到期时必须恢复它修改过的派生属性。例如破甲结束后恢复防御，减速结束后恢复速度倍率。

## 7. 被动系统

被动技能可以在战斗开始、每回合开始或行动过程中生效。

常见被动：

| 被动 | 效果 |
| --- | --- |
| 闪避 | 受击时概率完全躲避 |
| 连击 | 使用技能命中后追加一次普通攻击 |
| 反击 | 被攻击后立刻普通攻击反击 |
| 复活 | 死亡时按概率恢复一定生命 |
| 破甲 | 攻击命中后使目标破甲 |
| 吸血 | 造成伤害后按比例恢复自身生命 |
| 守护人物 | 减少来自人物的伤害 |
| 守护宠物 | 减少来自宠物的伤害 |
| 守护佣兵 | 减少来自佣兵的伤害 |

复刻时建议每回合结算前刷新一次被动字段，保证临时状态结束后仍能回到被动基础值。

## 8. 回合结算规则

一回合由双方所有存活单位依速度顺序行动一次。

完整流程：

1. 获取当前双方队伍。
2. 刷新或应用所有被动技能。
3. 取双方所有存活单位。
4. 按有效速度从高到低排序。
5. 如果速度相同，用随机值决定先后。
6. 从最快单位开始依次行动。
7. 如果行动前任意一方已经全灭，停止本回合。
8. 如果单位已阵亡，跳过。
9. 如果单位处于束缚、沉睡、眩晕或麻痹，跳过行动并递减状态。
10. 根据玩家提交的指令或自动逻辑确定行动。
11. 如果单位混乱，改为随机攻击任意其他存活单位。
12. 执行普通攻击、技能、治疗或增益。
13. 记录事件。
14. 行动后递减部分状态。
15. 所有单位行动结束后，结算流血和诅咒。
16. 递减全体回合状态。
17. 判断胜负。
18. 输出回合事件和双方最终生命状态。

胜负判断：

- 我方全灭且敌方未全灭，敌方胜利。
- 敌方全灭且我方未全灭，我方胜利。
- 双方都还有存活单位，战斗继续。
- 如果双方同时全灭，可按业务需要判定为平局、防守方胜利或最后行动方胜利。

## 9. 玩家控制逻辑

### 9.1 指令类型

战斗底部指令栏建议包含：

| 指令 | 行为 |
| --- | --- |
| 攻击 | 选择目标后普通攻击 |
| 技能 | 打开技能菜单，选择技能 |
| 道具 | 预留，可使用战斗道具 |
| 自动战斗 | 开启或关闭自动选择 |
| 逃跑 | 尝试结束 PVE 或请求退出战斗 |

### 9.2 单人控制顺序

每回合玩家按以下顺序下达指令：

1. 人物
2. 宠物
3. 佣兵

如果宠物或佣兵不存在，或已经阵亡，则跳过。

### 9.3 指令选择流程

手动流程：

1. 当前控制单位高亮。
2. 玩家选择攻击或技能。
3. 如果技能是自身增益、治疗或团队增益，可以直接确认。
4. 如果技能需要敌方目标，进入目标选择。
5. 玩家切换目标并确认。
6. 系统记录该单位本回合行动。
7. 切换到下一个可控制单位。
8. 所有可控制单位都选择完后，提交本回合选择。

### 9.4 目标选择

目标选择推荐规则：

- 默认目标为敌方第一个存活单位。
- 玩家可以在敌方存活单位之间切换。
- 全体技能仍然可以选择一个主目标，但实际命中所有敌人。
- 多目标技能以主目标为第一个目标，再按敌方列表补足其他目标。
- 治疗技能默认作用于己方，不需要选择敌方目标。

### 9.5 倒计时

每个选择阶段都有倒计时。

倒计时结束后，如果玩家未完成选择，自动开启自动战斗或自动提交默认行动。

推荐默认超时时间：15 秒。

## 10. 自动战斗逻辑

自动战斗可以由玩家主动开启，也可以由倒计时超时触发。

### 10.1 自动策略

每类单位可以设置策略：

- 始终普通攻击。
- 始终使用技能。
- 使用指定技能。
- 如果指定技能不可用，则使用默认技能。

宠物和佣兵可以按个体单独配置策略。

### 10.2 自动目标

自动行动默认选择敌方第一个存活单位。

如果敌方没有存活单位，则不提交行动。

### 10.3 自动行动优先级

生成自动行动时按以下顺序：

1. 如果单位被强制普通攻击，则普通攻击。
2. 如果策略是普通攻击，则普通攻击。
3. 如果策略是技能，检查指定技能是否可用。
4. 指定技能不可用时，使用该单位默认主动技能。
5. 如果没有可用技能，则普通攻击。

## 11. PVE 战斗流程

PVE 是玩家对怪物、Boss 或竞技场镜像的战斗。

PVE 可以由客户端本地结算，也可以由服务端结算。若目标是单机体验或弱联网体验，本地结算即可。若目标是强反作弊游戏，则建议服务端结算。

### 11.1 进入 PVE

流程：

1. 玩家触发怪物或 Boss。
2. 检查玩家是否已经在战斗中。
3. 检查玩家是否处于不可战斗状态，例如摆摊、转场、资源未加载。
4. 构建我方单位：人物、宠物、佣兵、队友单位。
5. 构建敌方单位：怪物、多个怪物、Boss、小怪。
6. 预加载战斗资源。
7. 隐藏地图上的参战角色。
8. 在地图上显示战斗标记。
9. 播放进入战斗转场。
10. 显示战斗界面。

### 11.2 PVE 回合

流程：

1. 玩家提交我方行动。
2. 系统为怪物生成自动行动。
3. 调用回合结算。
4. 播放回合事件。
5. 如果未结束，进入下一回合。
6. 如果结束，播放胜负表现。
7. 发放奖励或处理失败。
8. 退出战斗界面，恢复地图角色。

### 11.3 PVE 奖励

胜利奖励可以包括：

- 经验
- 金币
- 装备
- 材料
- 技能碎片
- Boss 特殊掉落
- 排名或积分

奖励应在战斗结束后只发放一次。建议使用战斗编号加奖励标记防止重复领取。

## 12. 单人 PVP 流程

单人 PVP 必须由服务端权威结算。

### 12.1 邀请阶段

攻击方流程：

1. 玩家选择另一个在线玩家为目标。
2. 检查双方不是队友。
3. 检查双方版本是否兼容。
4. 检查双方是否可战斗。
5. 生成战斗编号。
6. 广播战斗标记。
7. 向服务端发送挑战请求。
8. 等待防守方接受或拒绝。

防守方流程：

1. 收到挑战请求。
2. 检查自己是否在线、是否已在战斗、是否摆摊、资源是否可用。
3. 如果不能战斗，返回拒绝原因。
4. 如果可以战斗，加载资源。
5. 回复接受挑战。
6. 进入战斗界面。

### 12.2 服务端创建战斗

服务端收到接受消息后：

1. 根据攻击方账号读取服务端保存的角色数据。
2. 根据防守方账号读取服务端保存的角色数据。
3. 结合最新在线镜像补充外观、坐标、方向。
4. 重新计算人物、宠物、佣兵属性。
5. 创建服务端战斗状态。
6. 通知攻击方和防守方战斗正式开始。

注意：客户端上报的战斗属性不能作为可信数据。

### 12.3 PVP 回合

流程：

1. 攻击方客户端收集本方人物、宠物、佣兵行动。
2. 防守方客户端收集本方人物、宠物、佣兵行动。
3. 双方把本回合选择发送给服务端。
4. 服务端等待双方都提交。
5. 如果一方超时，服务端为其生成自动行动。
6. 服务端调用战斗引擎结算。
7. 服务端把同一个回合结果广播给双方。
8. 双方客户端只播放结果，不重新计算。
9. 如果战斗结束，服务端清理会话。

### 12.4 断线和取消

如果邀请阶段有人断线，取消邀请。

如果战斗阶段有人断线，可按产品需求处理：

- 直接结束战斗。
- 判定断线方失败。
- 暂停等待重连。
- 由自动战斗接管。

当前推荐简单方案：清理战斗会话，通知另一方战斗结束。

## 13. 组队 PVP 流程

组队 PVP 是多人对多人战斗。

### 13.1 队伍构建

服务端根据发起者和目标玩家获取双方队伍。

规则：

- 每边最多可限制 4 名玩家。
- 每名玩家可贡献人物、宠物、佣兵。
- 队伍成员必须在线。
- 队伍成员最好在同一地图或同一区域。
- 如果攻击方和防守方有相同成员，则禁止战斗。

### 13.2 开始组队战斗

服务端流程：

1. 收到挑战请求。
2. 判断是否需要组队 PVP。
3. 构建攻击方单位列表。
4. 构建防守方单位列表。
5. 创建服务端战斗状态。
6. 向所有参战玩家发送战斗开始消息。
7. 告诉每个客户端它能控制哪些单位。
8. 开启本回合选择倒计时。

### 13.3 组队选择

每个玩家只控制自己拥有的单位：

- 自己的人物
- 自己的宠物
- 自己的佣兵

客户端提交时，应使用战斗单位唯一编号绑定行动，不建议只用名字。因为多人宠物或佣兵可能重名。

### 13.4 组队结算

服务端流程：

1. 收集所有参战玩家提交的行动。
2. 如果全部提交，立刻结算。
3. 如果倒计时结束仍有人未提交，缺失单位使用自动行动。
4. 结算后把同一个结果广播给所有参战玩家。
5. 如果战斗未结束，清空选择，进入下一回合。
6. 如果战斗结束，广播结束消息并清理会话。

## 14. 战斗站位

站位需要同时满足清晰、好看、可扩展多人单位。

### 14.1 画面方向

推荐布局：

- 我方站在画面左侧。
- 敌方站在画面右侧。
- 我方面朝右。
- 敌方面朝左。

如果是防守方客户端，也可以仍然让“本机玩家”显示在左侧，但服务端结果需要做阵营映射。为了降低复杂度，更推荐所有客户端按服务端阵营显示，即攻击方左侧、防守方右侧。

### 14.2 单人队伍站位

单人携带宠物和佣兵时，推荐三角站位：

我方：

- 人物位于左侧中间。
- 宠物位于人物前下方。
- 佣兵位于人物后上方。

敌方：

- 人物或主怪位于右侧中间。
- 宠物或小怪位于主单位前下方。
- 佣兵或第二小怪位于主单位后上方。

### 14.3 多单位队伍站位

如果每边最多 12 个单位，可以使用三列或斜线阵型。

推荐规则：

- 人物优先放中列。
- 宠物放前列。
- 佣兵放后列。
- 同一玩家的三个单位尽量靠近。
- 单位越多，纵向间距越小，但不能重叠。

示例站位逻辑：

- 每边有 1 个单位：放中间。
- 每边有 2 个单位：上下分布。
- 每边有 3 个单位：上中下分布。
- 每边有 4 到 6 个单位：两列错位排列。
- 每边超过 6 个单位：三列错位排列。

### 14.4 坐标建议

以任意战斗画布为例，可以按百分比计算，不依赖固定分辨率。

我方基础区域：

- 横向范围：画面宽度的 18% 到 42%。
- 纵向范围：画面高度的 28% 到 72%。

敌方基础区域：

- 横向范围：画面宽度的 58% 到 82%。
- 纵向范围：画面高度的 28% 到 72%。

人物、宠物、佣兵的偏移：

- 人物：中心点。
- 宠物：向前、向下偏移。
- 佣兵：向后、向上偏移。

前后方向按阵营决定：

- 我方的“前”是向右。
- 敌方的“前”是向左。

### 14.5 层级遮挡

单位绘制顺序建议按脚底 Y 坐标从小到大排序。

脚底越靠下，越晚绘制，显示在更前面。

这样斜向站位时不会出现上方单位盖住下方单位的违和感。

## 15. 战斗动画

战斗动画由回合事件驱动。规则引擎只输出事件，表现层根据事件播放动画。

### 15.1 进入战斗动画

推荐流程：

1. 地图角色停止移动。
2. 显示战斗标记。
3. 播放转场遮罩，例如横向或纵向百叶窗。
4. 转场持续约 600 到 700 毫秒。
5. 显示战斗背景和双方站位。
6. 播放待机动画。

### 15.2 待机动画

待机动画用于让战斗画面有生命感。

推荐：

- 单位每 800 到 1200 毫秒轻微上下浮动。
- 武器或身体播放循环待机帧。
- 生命条和状态图标固定在单位头顶，不随身体大幅抖动。

### 15.3 普通攻击动画

普通攻击事件播放流程：

1. 攻击者切换攻击动作。
2. 攻击者向目标方向冲刺一小段距离。
3. 冲刺距离建议为 30 到 45 像素，或画面宽度的 3% 到 5%。
4. 到达冲刺顶点时播放命中特效。
5. 目标轻微受击后退或闪白。
6. 显示伤害数字。
7. 攻击者回到原站位。
8. 恢复待机动作。

建议总时长：700 到 1000 毫秒。

### 15.4 技能动画

技能事件播放流程：

1. 显示技能名称。
2. 施法者播放施法动作。
3. 根据技能类型播放对应特效。
4. 单体技能在目标身上播放命中特效。
5. 全体技能对多个目标依次或同时播放特效。
6. 显示伤害、治疗或状态文字。
7. 状态图标刷新。

技能名称显示建议持续 800 到 1000 毫秒。

全体技能可使用批次编号把多个命中事件归为一组，表现为同一次技能命中多个目标。

### 15.5 治疗动画

治疗事件播放流程：

1. 施法者播放施法动作。
2. 己方目标身上出现绿色、金色或柔和光效。
3. 显示绿色正数。
4. 如果目标复活，先播放复活文字，再让单位从倒地/消失状态回到待机状态。

### 15.6 状态动画

控制或异常状态命中时：

- 显示状态命中特效。
- 目标头顶出现状态图标。
- 日志记录状态名称。

状态图标建议固定为 16 到 24 像素，多个状态从左到右排列。

### 15.7 闪避动画

闪避事件播放流程：

1. 攻击者正常出手。
2. 目标快速侧移或闪白。
3. 显示“闪避”或“MISS”。
4. 不扣生命。

### 15.8 暴击动画

暴击事件可以增强表现：

- 伤害数字放大。
- 数字颜色使用更醒目的颜色。
- 屏幕短暂震动。
- 可播放暴击台词气泡。

### 15.9 流血和诅咒动画

回合末统一播放。

推荐：

1. 暂停普通行动。
2. 对每个受到持续伤害的单位播放小型特效。
3. 显示扣血数字。
4. 更新生命条。
5. 如果因此阵亡或复活，播放对应表现。

### 15.10 死亡和复活动画

死亡：

- 单位变暗、倒地、透明或显示红色叉号。
- 生命条归零。
- 不再参与后续行动。

复活：

- 显示“复活”文字。
- 播放上升光效。
- 恢复部分生命。
- 单位回到待机动作。

### 15.11 战斗结束动画

胜利：

- 我方播放胜利待机或庆祝。
- 显示奖励面板。
- 移除战斗标记。
- 返回地图。

失败：

- 显示失败提示。
- 恢复地图状态。
- 按业务处理复活点、惩罚或退出。

## 16. 战斗 UI

### 16.1 必要元素

战斗界面至少包含：

- 战斗背景
- 我方单位
- 敌方单位
- 生命条
- 状态图标
- 指令栏
- 技能菜单
- 目标选择指示
- 倒计时
- 战斗日志
- 伤害和治疗数字

### 16.2 生命条

生命条建议显示在单位头顶或脚下。

结构：

- 黑色或深色背景条。
- 红色当前生命条。
- 可选生命数字。

生命变化不要瞬间跳变，可以用 200 到 400 毫秒缓动。

### 16.3 目标指示

选中目标时应有明显指示：

- 箭头指向目标。
- 目标脚下光圈。
- 目标轮廓高亮。

箭头可以左右轻微摆动或上下浮动。

### 16.4 指令栏

指令栏建议放在画面底部。

当前可操作单位名称应清晰显示，例如“人物：某某”“宠物：某某”。

不可用指令应置灰或显示提示。

## 17. 事件结果格式

无论使用什么语言，回合结算结果都建议包含三部分：

第一部分是事件列表。事件列表用于播放动画。

第二部分是双方最终状态。它是本回合结束后的权威生命、阵亡、状态、增益快照。

第三部分是胜负结果。包含是否结束和胜利方。

事件至少应包含：

- 事件类型
- 攻击者唯一编号
- 防御者唯一编号
- 数值
- 是否暴击
- 防御者最新生命
- 防御者是否阵亡
- 是否复活
- 防御者最新状态
- 防御者最新增益
- 特效编号或表现类型

客户端播放动画时，不应该重新计算伤害，只能按事件和最终状态更新画面。

## 18. 网络同步

### 18.1 PVP 同步原则

PVP 的唯一真相在服务端。

客户端负责：

- 显示战斗界面。
- 收集玩家选择。
- 把选择发给服务端。
- 接收服务端结果。
- 播放动画。

服务端负责：

- 验证玩家身份。
- 验证战斗是否存在。
- 验证玩家是否属于该战斗。
- 重建可信战斗属性。
- 收集双方选择。
- 超时自动补行动。
- 结算回合。
- 广播同一份结果。
- 清理结束或断线战斗。

### 18.2 消息类型

单人 PVP 建议消息：

| 消息 | 用途 |
| --- | --- |
| 战斗标记开始 | 地图显示有人战斗 |
| 战斗邀请 | 攻击方向防守方发起挑战 |
| 接受邀请 | 防守方同意进入战斗 |
| 拒绝邀请 | 防守方拒绝或状态不允许 |
| 提交选择 | 一方提交本回合行动 |
| 回合结果 | 服务端广播权威结果 |
| 战斗结束 | 清理双方战斗状态 |
| 战斗标记结束 | 地图移除战斗标记 |

组队 PVP 建议消息：

| 消息 | 用途 |
| --- | --- |
| 组队战斗开始 | 通知所有队员进入战斗 |
| 组队提交选择 | 每个玩家提交自己单位的行动 |
| 组队回合结果 | 服务端广播权威结果 |
| 组队战斗结束 | 清理所有参战玩家状态 |

### 18.3 超时处理

每个 PVP 回合设置选择超时。

如果一方超时：

- 单人 PVP 中，为该玩家全部单位生成自动行动。
- 组队 PVP 中，只为未提交玩家控制的单位生成自动行动。

这样可以避免一名玩家卡住整场战斗。

## 19. 复刻开发顺序

推荐开发顺序：

1. 实现战斗单位数据结构。
2. 实现技能数据结构。
3. 实现有效属性计算。
4. 实现普通攻击。
5. 实现速度排序和完整回合。
6. 实现单体技能。
7. 实现全体和多目标技能。
8. 实现控制状态。
9. 实现流血、诅咒等回合末状态。
10. 实现治疗、复活、净化。
11. 实现被动技能。
12. 实现客户端指令选择。
13. 实现自动战斗。
14. 实现战斗站位。
15. 实现事件驱动动画。
16. 实现 PVE 完整流程。
17. 实现单人 PVP 服务端权威结算。
18. 实现组队 PVP。
19. 实现奖励、日志、断线清理。
20. 做平衡测试和压力测试。

## 20. 测试清单

规则测试：

- 普通攻击能造成正确伤害。
- 技能系数能正确参与伤害。
- 防御减伤不超过 90%。
- 暴击率和暴击伤害上限生效。
- 速度高的单位先行动。
- 速度相同能随机排序。
- 阵亡单位不会行动。
- 控制状态能跳过行动。
- 封印能阻止技能。
- 混乱能攻击队友。
- 全体技能能命中所有敌人。
- 多目标技能能命中指定数量。
- 治疗能恢复生命。
- 复活能让阵亡单位回到战斗。
- 流血和诅咒在回合末生效。
- 状态到期后正确移除。
- 被动连击、反击、吸血、闪避能触发。
- 任一方全灭后战斗结束。

流程测试：

- PVE 能完整进入、选择、结算、奖励、退出。
- PVP 双方都提交后才结算。
- PVP 客户端不会本地重算结果。
- PVP 一方超时会自动行动。
- PVP 断线后能清理会话。
- 组队 PVP 每个玩家只能控制自己的单位。
- 组队 PVP 未提交玩家不会卡住全队。

表现测试：

- 站位不重叠。
- 单位遮挡顺序正确。
- 目标箭头指向正确。
- 技能名、伤害数字、治疗数字不遮挡关键 UI。
- 全体技能多目标动画能正确播放。
- 死亡和复活动画与生命状态一致。
- 回合结束后画面状态与权威结果一致。

## 21. 重要注意事项

- PVP 不要信任客户端属性。
- 战斗单位必须有稳定唯一编号。
- 动画播放必须由事件驱动，不要反向推导规则。
- 回合结果必须包含最终状态快照，避免客户端状态漂移。
- 阵营显示和服务端阵营要有明确映射。
- 多人战斗不要用角色名作为唯一匹配依据。
- 添加新技能时，先定义技能参数，再实现规则效果，最后补表现动画。
- 调整数值公式时，要同时验证 PVE 和 PVP。
- 自动战斗不是只给怪物用，玩家超时和挂机也依赖它。
