# 龙魂系统跨项目复用说明

## 1. 系统目的

龙魂是一个**服务端权威的常驻角色养成系统**：玩家消耗 `灵魂粉末` 进行一次进化，按概率获得普通或暴击经验；经验满时提升龙魂等级，并把对应的累计属性加入角色和战斗属性。

默认共 7 个阶段、每阶段 10 级、总上限 70 级：

| 阶段 | 等级区间 |
| --- | --- |
| 黄铜 | 0–10 |
| 青铜 | 11–20 |
| 黑铁 | 21–30 |
| 白银 | 31–40 |
| 黄金 | 41–50 |
| 白金 | 51–60 |
| 钻石 | 61–70 |

`0` 表示尚未养成；`70` 表示满级。界面显示的阶段内等级为 `level % 10`，但 70 级特例显示为钻石 `10/10`。

## 2. 可直接复用的规则

### 进化规则

每次进化均由服务端完成以下步骤：

1. 从登录会话确定玩家身份；**不信任请求体中的账号、等级、经验、暴击或扣费结果**。
2. 在同一数据库事务中读取玩家当前状态、检查满级和灵魂粉末余额。
3. 服务端随机决定是否暴击：`random < criticalChance`。
4. 扣除一次 `cost` 灵魂粉末；普通进化增加 `normalExp`、消耗一次每日次数，暴击增加 `criticalExp`、**不消耗**每日次数。
5. 经验每达到一次 `expPerLevel` 就升 1 级，可连升；达到 70 级后经验清零。
6. 提交事务并返回数据库中的最新状态。

普通进化在每日次数已用尽时被拒绝，暴击进化不受该次数限制；二者都仍需消耗粉末。每日计数在服务端本地日期变化后自动重新从 0 计算，无须批量重置数据库。

### 属性规则

每个阶段配置的是该阶段 **10/10 时的属性总值**，阶段内线性增长，已完成阶段永久累计。对阶段 `i`（从 0 开始）、总等级 `L`：

```text
阶段贡献等级 = clamp(L - i × 10, 0, 10)
该阶段某属性贡献 = 阶段满级属性 × 阶段贡献等级 / 10
角色龙魂总属性 = 所有 7 个阶段贡献之和
```

结果保留两位小数。比如 1 级黄铜的攻击力为 `1000 × 1/10 = 100`；40 级则累计黄铜、青铜、黑铁、白银四个阶段的满级属性。

龙魂属性必须在**服务端最终属性计算**中合并，例如：

```js
finalStats[stat] = classGrowthAtLevel(stat, player.level)
  + dragonSoulStatsAt(player.dragon_soul)[stat]
  + equipmentAndOtherBonuses[stat];
```

客户端可以使用同一份纯计算规则展示预览，但战斗、排行和奖励结算只使用服务端计算结果。

## 3. 默认平衡配置

```json
{
  "cost": 50,
  "normalExp": 200,
  "criticalExp": 1000,
  "expPerLevel": 1000,
  "criticalChance": 0.3,
  "dailyLimit": 10
}
```

默认情况下，普通进化每次消耗 50 粉末、获得 200 经验；暴击概率 30%，获得 1000 经验；每级需要 1000 经验。普通进化每天最多 10 次。

支持的属性键如下；未配置的键按 `0` 处理：

```text
attack, speed, defense, mana, hp,
critDamage, antiCritDamage, hit, dodge,
confuseResist, sealResist, paralyzeResist, curseResist, sleepResist, crit
```

默认七阶段满级属性表：

| 阶段 | 攻击 | 速度 | 防御 | 法力 | 生命 | 暴伤/抗暴伤 | 命中 | 闪避 | 五种异常抗性* | 致命 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 黄铜 | 1000 | 50 | 500 | 100 | 10000 | 10 / 10 | 10 | 0 | 0 | 0 |
| 青铜 | 2000 | 100 | 1000 | 200 | 20000 | 20 / 20 | 10 | 0 | 0 | 0 |
| 黑铁 | 3000 | 150 | 1500 | 300 | 30000 | 30 / 30 | 10 | 0 | 10 | 0 |
| 白银 | 4000 | 200 | 2000 | 400 | 40000 | 40 / 40 | 20 | 10 | 20 | 10 |
| 黄金 | 5000 | 250 | 2500 | 500 | 50000 | 50 / 50 | 20 | 20 | 30 | 20 |
| 白金 | 7500 | 400 | 4000 | 750 | 75000 | 50 / 50 | 20 | 20 | 30 | 20 |
| 钻石 | 10000 | 500 | 5000 | 1000 | 100000 | 50 / 50 | 20 | 20 | 30 | 20 |

\* 五种异常抗性依次为：混乱、封印、麻痹、诅咒、昏睡；同一行的五项数值相同。

若目标项目的属性体系不同，只改属性键和阶段表；不要改变等级、经验和属性计算规则的真相源。

## 4. 数据库模型

最小玩家字段（SQLite 示例）：

```sql
ALTER TABLE players ADD COLUMN dragon_soul INTEGER NOT NULL DEFAULT 0;
ALTER TABLE players ADD COLUMN dragon_soul_exp INTEGER NOT NULL DEFAULT 0;
ALTER TABLE players ADD COLUMN dragon_soul_daily_key TEXT NOT NULL DEFAULT '';
ALTER TABLE players ADD COLUMN dragon_soul_daily_used INTEGER NOT NULL DEFAULT 0;
ALTER TABLE players ADD COLUMN soul_powder INTEGER NOT NULL DEFAULT 0;
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `dragon_soul` | 总等级，整数 0–70 |
| `dragon_soul_exp` | 当前等级内经验；满级固定为 0 |
| `dragon_soul_daily_key` | 上一次普通进化计数所属的服务端本地日期，格式 `YYYY-MM-DD` |
| `dragon_soul_daily_used` | 该日期已使用的普通进化次数 |
| `soul_powder` | 可扣除的灵魂粉末余额 |

运行时配置保存至 `app_settings`：

```sql
CREATE TABLE IF NOT EXISTS app_settings (
  key TEXT PRIMARY KEY,
  value_json TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
-- key: dragon_soul_config_v1
```

建议把所有配置写成完整 JSON，由服务端做白名单、类型与范围归一化；当前实现的边界为：费用/经验/每级经验 `1–1,000,000`，每日次数 `1–1,000`，暴击率 `0–1`，单项阶段属性 `0–1,000,000,000`。

## 5. 最小服务端接口

### 玩家进化

```text
POST /api/dragon-soul/evolve
认证：玩家登录会话
请求体：无需可信业务字段；即使兼容客户端传 account，也必须忽略它
```

成功响应：

```json
{
  "ok": true,
  "critical": false,
  "gainedExp": 200,
  "state": {
    "level": 0,
    "exp": 200,
    "stage": 1,
    "stageLevel": 0,
    "stageName": "黄铜",
    "dailyUsed": 1,
    "dailyRemaining": 9,
    "cost": 50,
    "expPerLevel": 1000,
    "soulPowder": 950,
    "stats": { "attack": 0, "speed": 0 }
  }
}
```

失败响应：

| HTTP 状态 | `error` | 条件 |
| --- | --- | --- |
| 401 | 由宿主鉴权层返回 | 未登录或会话无效 |
| 404 | `player_not_found` | 会话对应玩家不存在 |
| 409 | `max_level` | 已经 70 级 |
| 409 | `not_enough_powder` | 粉末不足本次费用 |
| 429 | `daily_limit` | 非暴击且普通次数耗尽 |

除认证失败外，以上业务失败不得扣粉末、不得增加经验或次数。

### 配置接口

```text
GET  /api/dragon-soul-config                # 可公开给客户端读取展示配置
GET  /api/admin/dragon-soul-config          # 管理员
POST /api/admin/dragon-soul-config          # 管理员，提交完整配置
POST /api/admin/dragon-soul-config/reset    # 管理员，删除覆盖配置并恢复代码默认值
```

管理接口必须复用目标项目的强管理员鉴权，不能让玩家修改概率、价格或属性。若配置公开会暴露未上线数值，可移除第一个公开 GET，改为将必要展示数据随玩家状态返回。

## 6. 原子性与接入要求

进化是货币扣减和经验发放的同一笔资产操作，使用数据库事务（SQLite 可用 `BEGIN IMMEDIATE`）：

```text
BEGIN IMMEDIATE
读取玩家和当天次数
校验：玩家存在、未满级、粉末足够、普通次数足够
服务端掷暴击并计算经验/等级/次数
UPDATE 玩家等级、经验、日期、次数、粉末余额
COMMIT
```

任一步失败均 `ROLLBACK`。不要先扣粉末、再在事务外发经验；不要让客户端传入 `critical`、`gainedExp`、`level` 或 `soulPowder` 作为结算依据。

玩家档案接口应返回 `dragonSoulState`，至少含 `level`、`exp`、阶段信息、`dailyRemaining`、费用、所需经验、粉末和累计属性。前端在每次进化后以接口返回的 `state` 覆盖本地展示状态，不能本地预扣或本地判定暴击。

## 7. 可移植模块边界

现有实现分为三个职责明确的部分：

| 文件 | 可复用职责 |
| --- | --- |
| `龙魂系统/shared.js` | 阶段名称、默认数值、等级规范化、阶段/累计属性纯计算；可同时供 Node 与浏览器加载 |
| `龙魂系统/server.js` | `createDragonSoulRuntime({ db, random, now })`：配置持久化、日切、事务进化、状态组装 |
| 宿主项目 | 会话鉴权、路由分发、玩家档案返回、最终角色/战斗属性合并、管理后台 UI |

迁移到其他项目时，复制前两项，替换宿主数据库访问和认证注入即可。保留 `random` 与 `now` 的注入点，既方便单元测试，也避免把随机数和时钟写死在业务逻辑里。

最低回归检查：普通进化会扣粉末、加普通经验并消耗次数；暴击加暴击经验但不消耗次数；次数耗尽时普通进化不扣任何资产；同一账号并发请求不会双花或出现负余额。
