# 宠物系统待确认清单

## 使用规则

本文件是宠物重做的唯一待确认登记。来源档案中的空壳 TODO、重复问题和聊天路径不再作为实施清单维护。关闭一项时必须记录确认结论、规则版本、证据位置和受影响的模板/接口。

`P0` 表示必须在迁移、资产消耗或正式上线前解决；`P1` 表示可先完成不影响资产安全的底座；`P2` 为资源展示或运营补充。

## P0：安全与迁移阻塞

| ID | 问题 | 当前风险 | 关闭条件 |
| --- | --- | --- | --- |
| PET-P0-001 | 旧宠物 ID 不是实例模型，选择、拥有、带出和技能学习使用的 JSON 字段口径不同 | 无法可靠验证“这只宠物属于谁”，不能承载交易、绑定、装备或培养资产 | 建立 `instanceId`、统一所有权读取路径和旧数据迁移方案 |
| PET-P0-002 | 旧选宠、免费领取和卷轴召唤链路仍可受客户端宠物 ID 影响 | 客户端可伪造宠物选择或注入拥有列表；新系统不能复用这条资产路径 | 服务端从规则/奖池决定模板，校验实例归属，停止信任客户端宠物 ID |
| PET-P0-003 | 单人战斗奖励未绑定服务器战斗票据，且缺少幂等与结果验证 | 可重复请求奖励，影响宠物经验、掉落和经济公平 | 在启用新宠物成长前，将奖励改为服务端战斗运行、票据校验、一次性结算和流水 |
| PET-P0-004 | 召唤、学习、贴纸等宠物资产写入缺少 `requestId`、版本冲突控制、专属流水和显式事务 | 重试、并发或中断可重复消耗/发放或丢失状态 | 所有变更动作采用实例版本、幂等表、事务和资产流水 |
| PET-P0-005 | CHJ 数字、旧 `petId`、模板主键混用 | 迁移时可能把时装资源当成模板，导致宠物、技能或动画错配 | 确认稳定 `templateId` 与完整四类资源映射；旧 ID 仅作兼容字段 |
| PET-P0-006 | 白色幻影、895 等资源/名称映射存在冲突 | 不能安全自动迁移当前玩家宠物或发放新宠物 | 对冲突记录逐条确认正式名称、别名、模板主键和四类 CHJ |
| PET-P0-007 | SS 第二版、分类摘要与独立资料卡存在矛盾 | 错误品类会影响投放、资质、技能和合成规则 | 以独立资料卡或用户确认建立正式分类表；冲突条目不进入配置 |
| PET-P0-008 | 统一属性上限的来源目标值与当前全角色配置不一致 | 只改宠物会造成角色、佣兵、战斗和界面规则分叉 | 确认跨领域唯一 `STAT_LIMITS` 版本及迁移/回归范围 |

## P1：玩法规则阻塞

| ID | 待确认内容 | 影响范围 | 临时策略 |
| --- | --- | --- | --- |
| PET-P1-001 | 五项资质的正式 `weightedQualification` 组合、百分比叠加位置与取整 | 属性引擎、面板、战斗 | 先实现可注入的纯函数与样本测试，不写死到实例 |
| PET-P1-002 | 三条普通经验曲线和升级经验表 | 升级与转生 | 使用版本化占位配置，不开放新成长入口 |
| PET-P1-003 | 野宠捕捉器、抵抗值、精灵球、每日免费机会和掉落规则 | 捕捉、背包、经济 | 仅建立实例模型，不开放捕捉 |
| PET-P1-004 | 种子/卷轴页面的 70% 和 100% 含义，以及随机抽取还是玩家选择 | 召唤、奖池、公平性 | 保留资料候选池，不调用资产消耗 |
| PET-P1-005 | 合成配方的主副宠、数量、成功率、失败产物与绑定策略 | 合成与交易经济 | 禁止二合、三合、四合、多提一、九提一上线 |
| PET-P1-006 | 资质宝石拆除、交易、打磨、孔位解锁和装备强化规则 | 宝石、装备、交易 | 50% 提取器仅保留设计基线，不开放接口 |
| PET-P1-007 | 缺失的技能卡资料、技能 ID 与当前 `战斗/skills.js` 的映射 | 技能槽与战斗 | 未找到服务端效果的技能标记 `pending`，不得按截图拼公式 |
| PET-P1-008 | 元素转换、家族资质、终极态、神力与守护养成度 | 战斗属性与后期养成 | 独立于基础成长，延后实现 |

## P2：资料与展示补充

| ID | 待补内容 | 处理方式 |
| --- | --- | --- |
| PET-P2-001 | CHJ 为 `无`、`待补` 或特殊字符串的资源预览 | 保留原始状态，实际预览后回填 |
| PET-P2-002 | 狐铃铛和恐惧木乃伊的资源组合 | 通过资源播放核对，不按编号模式猜测 |
| PET-P2-003 | 北极活动宠、历史名称卡的完整资质、技能、分类和时装 | 先建立待确认模板候选，不进入投放池 |
| PET-P2-004 | 旧名称统一与玩家可见显示名 | 用别名表兼容旧数据，确认后再做展示迁移 |
| PET-P2-005 | 宠物跟随、时装和战斗入场的表现规范 | 参考现有资源文档，独立于资产与成长实现 |

## 可立即推进的工作

以下工作不依赖 P0/P1 全部关闭，但不得写入玩家资产：

1. 建立 140 条模板候选的结构化审核表，使用 `status: pending` 或 `reference`。
2. 为 CHJ 表做字符串资源引用解析与预览工具，输出缺失和冲突报告。
3. 编写纯属性计算的测试向量，暂不连接玩家数据库。
4. 从 `server.js`、`app.js` 抽取旧宠物兼容逻辑到本领域模块，先保持行为不变。
5. 为现有宠物 API 建立只读行为测试和文档，再替换高风险写路径。
