# 宠物资料目录

## 1. 资料分层

本目录不把截图、攻略和历史总表直接变成运行时配置。正式模板应由一份结构化目录生成，资料只提供证据、待核对字段与导入候选。

| 层级 | 用途 | 能否直接写入运行时 |
| --- | --- | --- |
| 已确认运营模板 | 稳定主键、正式名称、分类、资质、技能 ID、资源引用 | 可以，须版本化与测试 |
| 已验证截图/代码证据 | 补全候选字段、校验模板 | 仅经人工确认后导入 |
| 设计推导 | 新区资质区间、成长与平衡建议 | 仅配置化试验，不覆盖旧实例 |
| 历史样本/攻略 | 合成路线、成本、成熟面板 | 不可直接实现资产消耗 |
| 待确认 | 资料矛盾、名称或资源未知 | 不可导入正式模板 |

## 2. 覆盖范围

三份来源资料可交叉得到 140 个唯一宠物名称：CHJ 表有 140 行，独立宠物资料卡也有 140 张，名称一一对应。该覆盖足以建立第一版“模板候选目录 + 资源候选目录”，但当前不能直接导出为正式模板配置。

资料按以下类别保存候选：

- 野宠，按带出等级 1、5、15、25、35、45、55、65、75 分段。
- 神兽、魂兽、圣兽、S 圣兽、SS 圣兽、珍奇、绝世。
- 战魂宠与北极活动宠。
- 已知名称但资质、分类、技能或资源未补齐的历史记录。

来源的早期分类总表存在错位。分类时应优先读取独立资料卡的明确分类证据，而不是直接相信章节标题：独立卡表明魂兽 5 只、圣兽 5 只、S 圣兽 10 只，但摘要章节混入了相邻品类。正式总览必须从唯一模板记录派生，禁止维护第二张手工总表。

## 3. 模板数据契约

正式模板目录至少应含以下字段：

```json
{
  "templateId": "stable-slug-or-opaque-id",
  "displayName": "正式名称",
  "aliases": ["历史名"],
  "category": "wild | divine | soul | holy | s_holy | ss_holy | rare | peerless | battle_soul | arctic",
  "releaseLevel": 1,
  "baseQualifications": {
    "hp": 0,
    "attack": 0,
    "speed": 0,
    "mana": 0,
    "defense": 0
  },
  "sourceQualifications": [],
  "innateSkillIds": [],
  "ordinarySkillIds": [],
  "recommendedOrdinarySkillIds": [],
  "spriteRefs": {
    "walkChj": null,
    "attackChj": null,
    "costumeWalkChj": null,
    "costumeAttackChj": null
  },
  "evidenceRefs": [],
  "status": "confirmed | reference | pending",
  "rulesVersion": "version"
}
```

`ordinarySkillIds` 是实际初始技能，`recommendedOrdinarySkillIds` 只是资料建议，二者必须分开。`sourceQualifications` 保留基础、红色、宝石、装备和样本来源，防止把截图中的培养增量当模板基础值。

`spriteRefs` 的值应使用字符串或 `null`。例如 `388b` 不是整数；CHJ 编号也允许多个宠物共用，不能附加唯一或连续编号假设。

## 4. CHJ 资源导入规则

CHJ 表包含四列：普通行走、普通攻击、时装行走、时装攻击。导入规则如下：

1. `无` 表示该资料明确没有该资源，保存为 `null`。
2. `待补` 表示资料未知，不能与 `无` 混用，保存为待核对状态。
3. 原始值以字符串保存，允许如 `388b` 的非整数引用。
4. 不猜测攻击号为行走号加一，不依据时装编号推导普通编号。
5. 同一个 CHJ 可以被多个宠物复用，不能加唯一约束。
6. 时装是否启用由实际拥有的时装状态决定；不能仅因模板配置了时装资源就默认展示。

已知需要资源复核的记录：狐铃铛的时装攻击值与相邻编号模式不一致；恐惧木乃伊的四类值组合与常见模式不同。两者都应保留原始值并通过实际资源预览确认，不能静默修正。

## 5. 合成、种子与资质资料

来源包含神奇宠物种子、召唤卷轴、提资类型、合成谱系、孔位、打磨和资质宝石样本。这些资料按以下规则归档：

| 内容 | 当前用途 | 实施状态 |
| --- | --- | --- |
| 种子候选池与界面百分比 | 记录候选关系与截图证据 | 待确认百分比语义和随机/选择机制 |
| 合成谱系 | 记录宠物之间的历史关联 | 不能视作主宠、副宠、数量或成功率配方 |
| 提资公式与成本路线 | 记录玩家反推结论 | 仅作平衡参考 |
| 资质提取器 50% | 可形成独立的服务端规则基线 | 仍需定义拆除、交易和物品 ID |
| 孔位与打磨 | 记录样本和建议上限 | 待确认解锁、效果与消耗 |

执行资质合成前，必须有唯一的结构化配方表，至少定义输入实例数、主副关系、消耗物、成功率、失败处理、绑定与交易结果、产物资质规则和规则版本。玩家 Excel 的“二合、三合、四合、多提一、九提一”不能直接转换为服务端动作。

## 7. 导入前检查

每批模板导入应满足：

1. 正式 `templateId` 唯一，正式名称唯一，别名不与其他正式名称冲突。
2. 分类由独立证据确认，不从旧章节标题推断。
3. 五项基础资质来自同一可信记录，培养增量、红色值、宝石值和百分比不混入。
4. 技能仅存稳定 ID；找不到当前战斗配置的技能标记为待实现。
5. 四类 CHJ 引用均显式填写 `null`、已确认值或待核对状态。
6. 每条记录有来源、可信度、规则版本和审核时间。
7. 不在导入脚本中修改玩家实例；模板更正通过新版本和迁移策略处理。
