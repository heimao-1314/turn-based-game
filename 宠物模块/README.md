# 宠物模块

## 文档状态

本目录是本项目宠物系统的领域落点。当前完成的是文档基线整理，不会因为这些文档而自动改变现有玩家宠物、货币、背包或战斗数值。

实现前先读本文，再按需要阅读 [宠物系统设计](./宠物系统设计.md)、[规则与数值](./规则与数值.md)、[资料目录](./资料目录.md) 和 [待确认清单](./待确认清单.md)。

| 范围 | 当前状态 | 后续边界 |

## 遗留安全状态

旧宠物选择、领取、召唤和单人战斗奖励链路尚不具备新系统要求的实例所有权、战斗票据、请求幂等和资产流水保障。它们只属于迁移前兼容层，不能作为新资产玩法的实现模板。具体阻塞项见 [待确认清单](./待确认清单.md) 的 `PET-P0-001` 至 `PET-P0-004`。

## 标识规则

以下标识绝不能混用：

| 标识 | 含义 | 规则 |
| --- | --- | --- |
| `templateId` | 稳定的宠物模板主键 | 新系统唯一模板主键；不从名称、CHJ 或旧数字推导 |
| `instanceId` | 玩家拥有的一只具体宠物 | 服务端生成；绑定、交易、培养、装备和战斗均以此为准 |
| `legacyPetId` | 旧系统宠物数字标识 | 仅用于兼容和迁移；允许为空 |
| `walkChj` / `attackChj` | 普通行走、攻击动画资源号 | 仅资源引用 |
| `costumeWalkChj` / `costumeAttackChj` | 时装行走、攻击动画资源号 | 仅资源引用；未配置时显式为 `null` |

例如，白色幻影的 CHJ 表同时有普通与时装资源号；它们不能充当模板 ID。现有目录中部分 `id` 实际使用时装行走号，因此迁移不得以 `id + 1` 或同类推导作为正式映射规则。

## 领域职责

宠物模块负责：

- 宠物模板、实例、所有权、绑定、交易限制和改名。
- 等级、经验、进化、转生、资质、天赋点和最终属性快照。
- 宠物技能槽、宠物装备、资质宝石及其服务端资产流水。
- 宠物模板与 CHJ 资源的显式映射。

宠物模块不负责：

- 战斗引擎的通用伤害结算，归 [`战斗/`](../战斗/) 负责。
- 通用背包物品的底层扣发，归已有资产/背包能力负责；宠物模块只提交已校验的消耗意图。
- CHJ 文件解析和帧播放，归 [`资源/文档/`](../资源/文档/) 及资源运行时负责。
- 贴纸生产配方，归 [`生活技能/贴纸生产.js`](../生活技能/贴纸生产.js) 负责；宠物模块只消费已结算的贴纸效果。

## 实施不变量

1. 账号身份只来自服务端会话，客户端不得提交或切换宠物所有者。
2. 所有会消耗道具、改变资质、绑定、交易、进化、转生或学习技能的操作都必须带 `requestId` 和实例版本，并在服务端事务内完成。
3. 模板是只读配置，实例只保存自身快照与培养差量；已有实例不可因模板改表被静默重算。
4. CHJ、技能 ID、物品 ID、显示名称均为引用字段，不能替代稳定模板主键。
5. 客户端仅展示服务器返回的属性快照；等级、随机结果、成功率、扣材和最终属性一律由服务端结算。
6. 未确认的合成配方、孔位路线、概率语义和成本结论不得启用资产消耗接口。

4. 先实现纯属性计算与迁移校验测试，再开放会消耗资产的进化、转生、提资或合成操作。
5. 新 API 进入本模块运行时后同步更新 `docs/API文档.md`。
