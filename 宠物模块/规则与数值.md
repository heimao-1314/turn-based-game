# 宠物规则与数值

## 1. 使用方式

本文件收录宠物系统的可实现规则基线。标记为“设计基线”的条目可用于写纯函数和测试；标记为“资料参考”或“待确认”的条目不能直接开放资产消耗或覆盖现有玩家数据。

具体宠物的资质、技能和分类不在本文复制维护，统一从 [资料目录](./资料目录.md) 对应的模板数据生成。历史证据在 `资料/` 下归档。

| 标记 | 含义 |
| --- | --- |
| 设计基线 | 已按来源资料整理为项目实施目标，但尚未替换旧运行时 |
| 资料参考 | 截图、样本或玩家计算表的结论，需版本化并验证 |
| 待确认 | 不足以形成正式规则，禁止直接写入经济/资产流程 |

## 2. 等级、绑定、进化与转生

### 2.1 等级边界（设计基线）

| 项目 | 规则 |
| --- | --- |
| 普通等级 | 1 至 100 |
| 普通经验 | 非负安全整数；零转、1 转、2 转使用独立经验曲线 |
| 进化等级 | 0 至 100，独立于普通等级与普通经验 |
| 最大转生次数 | 2 |
| 最高状态 | 2 转 100 级、进化 100 级 |

转生成功后普通等级回到 1、普通经验清零并切换下一条经验曲线；进化等级、进化天赋点和其已分配结果保留。经验曲线必须配置化，不能由属性公式反推。

### 2.2 绑定（设计基线）

- 绑定不可撤销，绑定后的宠物不可交易。
- 进化前必须绑定；未绑定时返回 `pet_binding_required`，不得自动绑定。
- 绑定、交易、放生、提取和合成均以 `instanceId` 为对象，不允许客户端指定所有者。

### 2.3 进化（设计基线）

宠物修炼册每本提供 `100` 点独立修炼经验。当前进化等级为 `L`（`0 <= L < 100`）时：

```text
requiredExp(L) = round(100 + L * 300 / 99)
```

从 0 级至 100 级的总需求为 `25,000` 点，即 250 本修炼册；每次突破还消耗 1 本进化书，共 100 本。

| 进化书 | 每次突破随机天赋点 | 每次突破可分配天赋点 |
| --- | ---: | ---: |
| 神品宠物进化书 | 3 | 1 |
| 魂品宠物进化书 | 2 | 2 |

流程：修炼经验达到当前阶段需求后，拒绝继续消耗修炼册；使用进化书后由服务端逐点生成随机天赋、提升进化等级，并把本阶段溢出经验结转到下一阶段。当前基线没有进化失败率，随机仅发生在随机天赋的四项落点（攻击、生命、速度、法力）中。

```text
canUseTrainingBook = evolutionLevel < 100 && trainingExp < requiredExp(evolutionLevel)
canEvolve = bound && evolutionLevel < 100 && trainingExp >= requiredExp(evolutionLevel)
```

### 2.4 转生（设计基线）

- 仅普通等级达到 100 的宠物可转生。
- 0 个或超过 2 个转生宝石的请求直接拒绝。
- 使用 1 个宝石时成功率 75%，失败仍消耗宝石但不改变等级、经验、转生次数、进化和天赋。
- 使用 2 个宝石时成功率 100%。
- 随机概率、材料数、结果和前后快照必须写入幂等结果与资产流水。

## 3. 点数模型（设计基线）

### 3.1 零转

从 1 升到 100 级时，每次升级获得五项各 1 点固定点，以及 2 点可分配点：

```text
fixedPointsPerStat = level - 1
preRebirthAssignable = 2 * (level - 1)
```

零转 100 级的固定点为 `99 * 5 = 495`，可分配点为 `198`。1 级不显示可分配或固定点，但拥有 1 个隐藏自然成长单位。

### 3.2 进化与转生

设神品进化次数为 `G`，魂品进化次数为 `H`：

```text
evolutionLevel = G + H
evolutionRandomPoints = 3 * G + 2 * H
evolutionAssignablePoints = G + 2 * H
```

满进化 100 次总共恒为 400 点。1 转在进入时获得 10 点，5 至 100 级的 20 个节点各 2 点，累计 50 点；2 转在进入时新增 20 点，20 个节点各 4 点，累计 150 点。来源中的满养成校验向量为：

```text
495（零转固定） + 198（零转可分配） + 400（进化） + 150（转生） = 1243
```

该向量用于测试总账，不能用平均值替代真实的四项随机天赋落点。

## 4. 资质与属性

### 4.1 出生资质（设计基线）

- 野宠在捕捉或生成时只随机一次五项出生资质，并将结果、档次、范围版本和带出等级写入实例。
- 非野宠使用模板固定出生资质；后续宝石、提资、装备等作为实例来源叠加，不能修改模板基准。
- 已保存实例的出生资质不得因菜单刷新、模板更新或客户端请求重新随机。

野宠四档权重：

| 档次 | token | 单项区间 | 权重 |
| --- | --- | --- | ---: |
| 差 | `white` | 最低值至区间 25% | 40% |
| 中 | `blue` | 25% 至 55% | 30% |
| 良 | `red` | 55% 至 80% | 20% |
| 优 | `gold` | 80% 至最高值 | 10% |

对每一个属性独立抽取档次与数值：

```text
span = maxQualification - minQualification
tier = serverRandomWeighted(white: 40, blue: 30, red: 20, gold: 10)
value = randomInteger(tier.lower * span, tier.upper * span) + minQualification
value = clamp(value, minQualification, maxQualification)
```

带出等级对应的首版范围、样本和证据见 [来源资料](./资料/来源-宠物系统开发文档.md)。上线时必须把范围版本固化在实例中，不能修改旧实例。

### 4.2 资质来源（设计基线）

```text
base     = 模板固定值或野宠出生值
red      = 红色/加成资质
card     = 资质卡等独立来源
gemCard  = 宝石卡、装备或镶嵌来源
```

存储字段可调整，但每项来源都必须可审计、不可重复累计。资质宝石进入单一来源后，不能又被防御或其他汇总字段重复加算。

### 4.3 属性公式（资料参考，先写测试向量）

换算系数：

| 属性 | 每 1 点属性所需资质 |
| --- | ---: |
| 生命 | 27.77 |
| 攻击 | 277.77 |
| 速度 | 2081.51 |
| 法力 | 1388.73 |
| 防御 | 277.77 |

来源设计稿采用 `petQualificationScale = 4` 作为 1 级隐藏自然成长单位的倍率：

```text
birthGrowthUnits = 1
levelGrowthUnits = level - 1
talentGrowthUnits = evolutionRandom + allocated

birthStat = baseQualification * 1.1 / coefficient
          * petQualificationScale * birthGrowthUnits
pointGrowthStat = weightedQualification / coefficient
                * (levelGrowthUnits + talentGrowthUnits)
rawPetStat = birthStat + pointGrowthStat
```

实施时必须先确认 `weightedQualification` 的来源组合、百分比叠加位置和统一取整，再将公式转为共享纯函数。保留原始小数；显示值与战斗值由同一取整策略生成。资质大于 0 而取整为 0 时，来源建议显示至少为 1。

### 4.4 最终上限（设计基线，需跨领域确认）

来源设计稿建议人物、佣兵和宠物共用以下最终上限：生命 `5,000,000`，攻击和防御各 `500,000`，速度和法力各 `100,000`。

```text
effectiveStat = min(rawStat, hardCap)
```

当前项目的共享上限仍是旧值，因此此项不能只在宠物模块改动。实施前必须确认跨人物、佣兵、宠物的一份共享配置和完整回归测试。

## 5. 技能、装备与资质宝石

### 5.1 技能槽（设计基线）

| 槽位组 | 数量 | 来源 |
| --- | ---: | --- |
| 主动神符 | 1 | 主动神符道具 |
| 英雄神符 | 1 | 英雄神符道具 |
| 编号神符 | 3 | 编号神符道具 |
| 普通技能 | 3 | 宠物技能卡 |
| 天生技能 | 1 | 模板引用 |
| 宠物法宝 | 最多 3 | 当前穿戴法宝 |

成熟宠物的理论上限为 12 项。普通技能的随机学习、覆盖、神符写入、法宝穿戴均须由服务端生成结果并保持幂等。模板的“推荐普通技能”与“初始普通技能”必须分开保存，不能把推荐误实现为强制技能。

技能效果的唯一代码来源应为 [`战斗/skills.js`](../战斗/skills.js) 及后续共享技能配置；宠物资料卡只引用 `innateSkillIds` 或普通技能 ID。

### 5.2 资质提取器（设计基线）

- 提取比例为来源宠物五项可提取资质的 50%。
- 提取会消耗来源宠物及其培养、装备和资质状态。
- 结果为携带五项资质的宝石；限定模板时必须校验目标 `templateId`。
- 已镶嵌宝石默认不参与再次提取；绑定来源产生的宝石继承不可交易状态。
- 提取、镶嵌、拆除和打磨都必须在事务中处理实例锁、版本、幂等和流水。
